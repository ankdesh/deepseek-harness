# Agent Note: 产品拥有的原生分发

Status: implemented

[English](2026-09-15-product-owned-native-distributions.md) | 中文

## Problem

独立应用在开发时需要本地 Harness 修改，在部署时需要小型运行时。安装标准 CLI 依赖会引入无关产品包组合；另建产品代理循环则会重复 Harness 生命周期管理。

## Decision

分叉仓库拥有通用开发链接、配置档准备和原生依赖组装工具。每个产品拥有自己的配置档包组合及部署配方。两种模式都启动标准 dsh CLI。打包器原样复制已构建的 CLI 代码，并从构建模块的导入推导部署依赖列表。

包图保留局部依赖链接，并在安装根目录暴露所选包供 Cordis 导入。打包器保留完整的构建 lib 目录，包括 lib/types 中被运行时引用的编译文件。Harness 提交不匹配或输出目录已存在时，打包器拒绝执行。分发元数据记录源提交、未提交修改状态、锁文件哈希、打包器哈希、平台及包列表。

## Alternatives considered

**安装完整标准 CLI 后禁用插件。** 禁用的插件仍保留已安装依赖。选择部署包图可以移除无关包。

**将代理循环复制到每个产品。** 独立循环重复运行时行为并增加上游更新难度。产品插件组合现有循环。

**在分叉仓库之外维护平台仓库。** 通用工具规模小且依赖 Harness 构建产物约定，因此目前由分叉仓库拥有。

## Consequences

产品共享构建机制，同时保留独立运行时配置和状态。原生分发面向构建平台，并需要单独配置平台运行时。产品拥有端到端执行、持久化、UI 和目录移动测试；配置档文件系统测试位于共享辅助函数旁。

已实现的接口参见[产品分发](../../../../docs/product-distribution.zh.md)。
