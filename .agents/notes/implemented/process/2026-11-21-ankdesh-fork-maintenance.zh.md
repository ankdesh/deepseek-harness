# Agent Note: ankdesh-dsh 分支维护

Status: implemented

[English](2026-11-21-ankdesh-fork-maintenance.md) | 中文

## 问题

分支、上游和首个应用的变更可以独立进行。两个编码代理需要遵守相同的规则。

## 决策

[分支规则](../../../ankdesh/constitution.md)为两个代理提供相同的说明，并将分支规则放在独立目录中。根说明文件保留一个链接。[发布流程](../../../ankdesh/release.md)将经过测试的包和发布记录存放在私有仓库中。

框架配置定义发布包的根集合。固定版本的 spec2gds 应用通过命名配置验证已选包。若应用依赖不在已选集合中，候选版本验证失败。 候选包注册服务从归档文件读取元数据，因此验证重命名的包时无需使用暂存目录。

## 考虑过的替代方案

独立源码工作区需要另一套构建和跨仓库兼容性检查。分支保留一个工作区，并以发布包作为应用接口。

## 后果

更新上游基线时检查以下修改：

- 会话注册识别分支事件类型。事件账本和流程运行时测试覆盖恢复及回放。
- SDK 协议和服务器传递工作流状态。SDK 服务器测试覆盖 RPC 行为。
- Web 启动使用应用自己的界面加载指定运行时。启动测试和组装后的 Web 配置检查覆盖此行为。
- 子代理结构化输出允许并行调用同一个工具。结构化驱动测试覆盖输出约定。若同步更改并行处理，则添加专项检查。

## 首次同步上游

此次同步合并 `0.2.2-rc.5`，并使用新的 DSH_HOME。旧版本保留其 V3 数据。 请参阅[升级指南](../../../../docs/upgrade-guide/v0.2.2-rc.5/ankdesh-fresh-state/guide.zh.md)。

- 事件系统和原生流程模型使用 V4 事件来源。原生流程模型读取独立的工具结果消息。 流程和事件运行时测试覆盖审核、等待、恢复和回放。
- 合并后的子代理结果处理允许并行重复调用同一个工具，并保留首个有效结果。 结构化输出测试覆盖重复调用。
- Web 运行时包负责启动策略。工作区继续使用同一个新建会话处理器。 部署规则可以限制语言列表并隐藏语言选择器，同时保留已保存的偏好。 Web 启动与客户端测试覆盖这些行为。
- 浏览器流程控制使用常规远程接口。LiveShare 仅允许所有者调用六个流程接口。
- 上游设置包和代理预设包已更名。取消归档设置已移至常规设置。 应用配置须使用当前包，并加载选定的工具执行器。
