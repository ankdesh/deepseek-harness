# Agent Note: HTTP 观察、持久等待与有界恢复

Status: implemented

[English](2026-10-01-event-http-waiting-recovery.md) | 中文

## Problem

对话智能体需要响应 owner 变化，并等待精确外部决定，在空闲时不消耗模型请求。失败恢复必须区分可安全重复的读取与不确定的 owner 副作用，并保留原有预算。

## Decision

[对话事件服务](2026-09-30-conversation-event-agents.zh.md) 支持声明为可安全重放的订阅，通过持久、有界指数退避重试。每次尝试保留独立投递及原生收据。中断尝试仍要求人类明确承认结果不确定。人类、事件及审核等待持久化精确未来响应关联。主目标等待记录已阻塞原生目标修订；匹配响应仅恢复该修订且要求有剩余轮次。暂停、停止、重启及预算耗尽保持接纳权限。

`dsh-event-system-http` 观察获准、有界 JSON GET 端点。服务先持久化防抖候选和发布 outbox，再使用稳定来源／序号身份发布。游标确认发生在事件提交之后。此顺序允许崩溃后重复发布，由事件账本去重，同时防止已确认变化丢失。来源配置仅包含凭据环境变量名。不变量配套插件根据独立提交的事件检查确认，并拥有观察器销毁。

## Alternatives considered

**先实现 webhook。** 用户选择 HTTP 条件轮询。轮询可使用已有 owner 端点，不必添加可访问、经身份验证的接收器。其他来源可使用相同活动状态发布契约。

**重试所有失败或中断激活。** 因独立变更可能在确认前成功而拒绝。只有人类拥有且声明可安全重放的订阅选择自动重试；重启不确定工作仍手动处理。

**触发或响应时刷新预算。** 因外部流量可绕过宿主预算而拒绝。所有尝试及原生续行保留固定对话分配。

## Verification

真实 Loader 组合覆盖未变化检查不调用模型、突发防抖、相等进入、无效端点及响应、并发来源上限、游标／outbox 崩溃恢复、原生人类等待及完成、有界失败投递重试。已提交无需密钥的原生会话快照固定人类等待及目标续行。负向配套插件测试检测缺失发布，并验证销毁与重新注册。产品组合覆盖两个 preset、HTTP 驱动分析／审核后的提案准备、精确审核丢弃唤醒、owner 隔离及未变化 focused 重放。

## Consequences

轮询增加有界网络流量及检测延迟。游标／事件去重不保证另一个 owner 存储中的恰好一次副作用。等待和事件容量有限。新等待及退避字段为可选，因此旧版本 1 记录可加载；旧二进制不必能读取扩展记录。可视编排及工作流执行不属于此变更。
