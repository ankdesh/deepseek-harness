# Agent Note: 分离工作流预设与服务适配器

Status: implemented

[English](2026-09-22-configurable-prompt-and-workflow-catalogs.md) | 中文

## 问题

产品助手存在两种相互独立的变化。用户选择工作如何运行：专注的一次交互、有界的
同会话目标工作，或有界编排。所选产品服务则独立决定助手知道什么、能做什么：
提示词、语义工具、绑定规则和审核约定。如果把两个选择编码在同一个 profile 中，
就会为每个“服务 × 预设”组合重复策略，并使新增服务变成不安全的组合修改。

提示文本与工具指导还需要精确、可检查的身份。运行时代码常量没有启动校验、内容
摘要或声明式产品路径。既有的模型编写 JavaScript 工作流解决的是另一类问题，并
授予服务工作流不需要的执行权限。

## 决策

DSH 现在提供启动期提示目录与宿主拥有的服务工作流域。

`dsh-prompt-catalog` 注册带版本的提示包，计算规范化 SHA-256 身份，绑定显式变量，
确定性排序各节，并在启动后封存。其 YAML 提供者只接受可信部署数据，并拒绝指令、
自定义标签、别名、锚点、合并键、非字符串键、重复键、未知字段及超限文件。它不
执行表达式，也不热重载提示文本。

`dsh-s-workflow` 为通用工作流定义与服务适配器维护独立目录。一次运行会快照定义和
适配器的精确摘要、用户选择的 `focused`、`goal` 或 `orchestrated` 预设、不可变服务
约定、资源预算与用量、审核草稿、检查点以及待处理的人类决策。每个 Session 只能
有一个未终止运行。每次变更使用精确运行修订号，并追加完整的
`s-workflow/change` 快照。

生命周期权限被有意分离。部署或人类拥有的调用负责启动、暂停、恢复、取消、回答、
批准完成及提高预算。通用模型工具只能读取状态、替换审核草稿、记录进度与用量、
请求必要输入或请求完成审核；它们不能应用或发送产品工件。服务适配器继续负责语义
提案工具与显式审核卡片的变更边界。

YAML 工作流词汇是声明式且封闭的：包含模型、审核、委派和检查点步骤及其文字说明，
不包含代码、表达式、导入或任意插件配置。既有 DSH 目标和一次性 subagent 提供者
仍是预设选用的执行机制；目录记录并治理产品工作流，而不重新实现这些机制。

必需的工作流事件继续使用 Session 格式 v3。新增普通必需事件不改变信封。当前
构建认识该事件；旧构建的静态已知事件集合会拒绝包含该不可忽略事件的日志，因此
会安全失败，而不会静默重建不完整工作流。

## 曾考虑的替代方案

**为每个服务和执行模式创建一个预设。** 拒绝，因为笛卡尔积会重复提示、工具和
预算策略，并使服务接入修改执行策略。

**使用既有模型编写的工作流引擎。** 拒绝用于此场景，因为可信的声明式产品工作流
不需要 JavaScript 执行，且模型不应拥有生命周期或变更权限。

**让适配器选择执行预设。** 拒绝，因为会话是专注、长时还是编排，应由用户决定。
服务适配器贡献领域能力，但不能扩大自主权。

**只持久化转换增量。** 拒绝，因为完整快照让重放、投影缓存、审核和兼容性检查
保持自包含，并与其他 DSH 状态域一致。

**把事件标记为可忽略。** 拒绝，因为省略该事件会改变持久工作流重建；不理解它的
读取器必须拒绝日志。

## 后果

产品可以提供精确适配器、提示包、工具和审核约定来新增服务，同时复用相同的三个
执行预设与通用工作流定义。提示和工作流启动失败是确定性的，持久运行能够命名其
使用的精确内容。

目录仅存在于进程内，并且只在启动时构建。恢复已存运行前，部署必须还原所引用的
版本和摘要。调度、同会话目标续跑、子 agent 进程上限和服务专用审核渲染仍由独立
组合负责；工作流域不会假装强制执行属于其他运行时的限制。
