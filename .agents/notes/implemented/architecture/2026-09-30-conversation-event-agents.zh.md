# Agent Note: 持久对话事件智能体

Status: implemented

[English](2026-09-30-conversation-event-agents.md) | 中文

## 问题

产品重复分析／审核请求需要持久专家记忆和宿主拥有的消耗计量。一次性委派重置身份，模型报告的工作流检查点无法观察每个原生请求。目标还需要不依赖可执行工作流定义的有界原生续行。

## 决策

`dsh-event-system` 和 `dsh-event-system-yaml` 提供通用对话事件服务与严格 YAML/Markdown 加载。把类型化发布及固定订阅投递持久化，复用原生会话，分别观察原生收据和轮次结束，并在访问提供方前计量发起者请求。产品 adapter 保留不可变所有者绑定和提案／审核权限。人工暂停、恢复、停止和承认不确定性的重试使用已观察修订号。重启要求人工恢复，不自动重放不确定投递。

既有[提示词和工作流目录决策](../../implemented/architecture/2026-09-22-configurable-prompt-and-workflow-catalogs.zh.md)保持有效，因为通用服务和历史 Session 解码仍存在。本决策替换产品编排组合，不替换独立包 API。原生[事件溯源 Session 决策](../../implemented/architecture/2026-06-11-event-sourced-sessions.zh.md)继续负责模型可见输入；事件投递进入普通已记录收件箱。

## 考虑过的替代方案

**首版实现工作流。** 用户明确延后工作流设置。固定订阅满足当前协作需求，无需图调度、汇合或第二套模型循环。

**仅在产品内实现原型。** 拒绝，因为 agent 身份、收据、接纳和资源所有权是可复用的原生执行职责。产品仍拥有语义工具和所有者修改。

**自动重放中断工作。** 拒绝，因为独立所有者副作用可能先于收据持久化成功。人工承认创建独立有界尝试并保留历史。

## 验证

真实 Loader 组合执行通用示例和原生目标续行，覆盖持久会话、有界计量、暂停／停止和人工重启恢复。产品组合覆盖两种预设的所有者提案准备、专家只读能力、原有 focused 行为及审核状态。解析、完整性、失败和取消回归拒绝无效接纳。源码设置将编译依赖和工具链链接到原生运行时使用的同一 fork。针对性 Harness 测试与产品集成测试通过；发布和固定修订更新仍是独立工作。

## 后果

独立原生日志、投递账本和所有者存储不能保证 exactly-once 修改。保守 token 预留可能较早拒绝大上下文。事件历史有限。外部触发、自动重试、通用持久等待、配置编辑和工作流不属于本阶段。
